# 工作流詳解

本文件補充 `SKILL.md` 的七個階段，說明每一步怎麼做、何時停下確認、以及從中途切入的方式。

## 階段之間的資料流

```
需求卡 ─▶ 企劃書 ─▶ 角色表 ─┐
                │            ├─▶ 分集大綱 ─▶ 劇本 ─▶ 分鏡 ─▶ AI 提示詞
                └────────────┘
                         每個階段結束 ─▶ 品質自檢
```

下游只讀上游成品，不回頭讀對話記錄。因此上游成品要寫完整，不能依賴「前面說過」。

## 切入點判斷

| 使用者給的東西 | 從哪個階段開始 | 需要補齊的前置 |
|----------------|----------------|----------------|
| 只有一個點子或題材 | 階段 0 | 無 |
| 一段故事梗概或小說 | 階段 1 | 從原文反推需求卡 |
| 已有企劃與角色 | 階段 3 | 檢查角色表欄位是否齊全 |
| 一集劇本 | 階段 5 | 從劇本反推角色外型，標註「推定」 |
| 分鏡表 | 階段 6 | 需要角色外型；缺少時先補角色表 |
| 任一成品＋「幫我檢查」 | 階段 7 | 無 |

## 各階段步驟

### 階段 0：需求釐清

1. 從使用者訊息中抽出已知資訊，填入需求卡。
2. 列出未知但會影響故事的欄位，合併成一次提問（最多 5 題，每題附預設值）。
3. 使用者說「你決定」或沒有回應某題時，採預設值並記錄於「採用的假設」。

### 階段 1：企劃書

1. 寫 3 個不同方向的 Logline，填入企劃書的「Logline 候選」表，請使用者選一個（使用者已明確指定時跳過；使用者要求一路做完時自行選定並在表中標明，不停下）。
2. 選定後展開：賣點、三幕結構、付費卡點、世界觀、禁忌。
3. 自檢：Logline 是否能在 5 秒內讓人想看第一集？

### 階段 2：角色表

1. 先定主角，再定與主角目標直接衝突的反派，最後補助攻與功能角色。
2. 每個角色寫出「表面身分／隱藏身分」，至少一個主要角色的隱藏身分會在中段揭露。
3. 填寫關係矩陣，確認每對主要角色之間都有張力或情感連結。

### 階段 3：分集大綱

1. 先畫出全劇情緒曲線的骨架（每 10 集一個小高潮，付費卡點前情緒拉到最低；12 集以下依 `pacing-rules.md`「迷你劇」換算）。
2. 逐集填表。每集只推進一個主要事件。埋下的伏筆同步記入「伏筆追蹤」表。
3. 集數超過 20 時分批產出；每批結束後摘要情緒曲線並確認。

### 階段 4：劇本

1. 一次寫一集，或使用者指定的集數區間。
2. 先寫結尾鉤子，再回頭寫開場，最後填中段（確保開頭結尾都夠強）。
3. 標記爽點、反轉、鉤子位置，並估算時長。超時就刪對白，不刪動作衝突。

### 階段 5：分鏡

1. 多集作品預設先做第 1 集，完成後詢問要補哪些集數。
2. 依劇本場次拆鏡，每個情緒轉折至少一個特寫。
3. 對白長的段落用正反打，避免一個鏡頭超過 6 秒。
4. 爽點那一鏡加上慢動作、推鏡或音效重擊的標註。

### 階段 6：AI 生成提示詞

1. 先產出每個角色的定裝圖提示詞，作為後續所有鏡頭的參考。
2. 為反覆出現的地點建立場景錨點。
3. 逐鏡轉寫，角色與場景都用 `[代號]` 佔位，送出前換成錨點全文，維持一致性。
4. 標註每鏡的生成方式：圖生影片（有主要角色）、文生影片（空鏡、環境）、文生圖＋圖生影片（物件特寫、多人互動）。

### 階段 7：品質自檢

依 `quality-checklist.md` 逐項檢查，在成品末尾附上結果表格。

## 停下確認的時機

- 階段 1 選 Logline 時
- 每個階段完成時（一句摘要＋「要繼續下一階段嗎？」）
- 分集大綱、劇本、分鏡每批產出後
- 發現上游成品有矛盾、需要回頭修改時

使用者說「一路做完」「不用問我」時，連續執行到指定階段，只在矛盾無法自行判斷時停下。

## 修改與版本

- 修改上游成品後，提醒使用者哪些下游成品可能受影響。
- 中繼資料的 `version` 遞增，`changelog` 記一行改了什麼。
